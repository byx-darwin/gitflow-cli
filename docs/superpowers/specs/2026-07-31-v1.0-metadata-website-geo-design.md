## 3. 设计：crates.io 元数据

### 3.1 工作区集中（`Cargo.toml` 的 `[workspace.package]`）

集中维护可继承字段，各 crate 通过 `field.workspace = true` 继承：

```toml
[workspace.package]
version = "0.9.0"                                  # 本次不改
authors = ["byx-darwin <baoyx19870908@gmail.com>"]  # 清除 Your Name
edition = "2024"
rust-version = "1.96.0"
license = "MIT"
homepage = "https://byx-darwin.github.io/gitflow-cli"   # 指向官网
repository = "https://github.com/byx-darwin/gitflow-cli"
readme = "README.md"
# documentation 按 crate 分别指向 docs.rs（见 3.2），不放 workspace
```

### 3.2 各 crate 独立字段

每个 crate 的 `[package]`：

- `description`：中文主导 + 一句英文。示例：
  - `gitflow-cli`（app）：`跨平台 Git 工程化工作流编排框架 CLI：统一封装 GitHub / GitLab / GitCode，配合 AI Agent Skills 覆盖需求到发布的完整工程循环。Cross-platform Git engineering workflow CLI.`
  - `gitflow-cli-core`：`gitflow-cli 核心库：Platform trait 抽象、跨平台适配器与 toon 输出。Core library: platform abstraction, adapters & toon output.`
  - `gitflow-cli-github` / `-gitlab` / `-gitcode`：`gitflow-cli 的 <平台> 适配器，基于 <gh|glab|gitcode> CLI。GitHub/GitLab/GitCode adapter for gitflow-cli.`
- `documentation = "https://docs.rs/<crate-name>"`
- `keywords`（≤5，含中英文检索词）：如 `["git", "workflow", "cli", "工作流", "ai"]`
- `categories`：如 `["command-line-utilities", "development-tools"]`
- `homepage.workspace = true` / `repository.workspace = true` / `authors.workspace = true` / `license.workspace = true` / `edition.workspace = true` / `rust-version.workspace = true`

### 3.3 GitHub 仓库 description

设为规范一句话定位（中文规范句，与 crates.io 描述首句逐字一致；crates.io `description` 字段本身按 §3.2 采用"中文主导 + 一句英文"以兼顾全球可发现性）。执行方式：`gh repo edit --description "<规范文案>"`。在 Phase 4 dogfooding 中执行并验证，同时在发布准备清单中登记为一步。

## 5. 设计：官网骨架 + GEO 地基

### 5.1 目录结构

```
website/
├── astro.config.mjs        # site / base=/gitflow-cli / @astrojs/sitemap / mdx
├── package.json            # astro, @astrojs/sitemap, @astrojs/mdx（npm）
├── public/
│   ├── llms.txt            # GEO 摘要（checked-in 源文件）
│   ├── llms-full.txt       # GEO 全文（checked-in 源文件）
│   ├── robots.txt          # 放行 AI 爬虫，指向 sitemap + llms.txt
│   └── favicon.svg
└── src/
    ├── layouts/Base.astro  # <head>：JSON-LD(SoftwareApplication) + meta + canonical
    ├── pages/
    │   ├── index.astro          # hero：一句话定位 + demo.svg + 安装
    │   ├── docs.astro           # 文档索引（链接渲染后的 docs/）
    │   ├── quickstart.mdx       # 5 分钟快速上手
    │   ├── compatibility.astro  # 构建期读取 docs/compatibility-matrix.json 渲染
    │   └── changelog.astro      # 渲染 CHANGELOG.md
    ├── components/              # Header / Footer / InstallTabs / CompatTable
    └── styles/global.css        # 原生 CSS，明暗双色
```

### 5.2 页面与数据源

| 页面 | 数据源 | 说明 |
|------|--------|------|
| 首页 `index` | 规范文案 + `demo.svg` | hero + 安装命令 + 特性三段 |
| 文档 `docs` | `docs/` 索引 | 骨架阶段为导航页，链接仓库 docs/ 与后续文档站 |
| 快速上手 `quickstart` | MDX | 安装→装 skills→验证→首次工作流 |
| 兼容性矩阵 `compatibility` | `docs/compatibility-matrix.json` | **构建期** `import`/读取 JSON 渲染表格，保证与仓库数据单一来源同步 |
| 更新日志 `changelog` | `CHANGELOG.md` | 构建期渲染 Markdown |

### 5.3 演示 SVG 生成管线

- `scripts/gen-demo-svg.sh`：用脚本驱动一段真实会话（`--help` / `skills list` / `issue list --output toon` 等只读命令），经 `asciinema rec` 录制、`svg-term` 渲染为 `docs/assets/demo.svg`。
- `asciinema` 与 `svg-term-cli` 仅为**开发期工具**，不进仓库依赖；`demo.svg` 作为提交产物入库，脚本保证可复现。

### 5.4 GEO 地基文件规范

- **`llms.txt`**：标准头部 —— `# gitflow-cli` 标题、blockquote 规范一句话定位、分节链接（Docs / Quick Start / Compatibility / Changelog / crates.io / GitHub）。
- **`llms-full.txt`**：全文材料 —— 定位说明、完整 CLI 命令参考、架构概述、兼容性矩阵、FAQ。供 AI 搜索引擎（Perplexity / ChatGPT / Kimi / 豆包）准确引用。
- **`robots.txt`**：放行主流 AI 爬虫（`GPTBot` / `PerplexityBot` / `ClaudeBot` 等），声明 `Sitemap:` 与 `# llms.txt:` 指引。
- **JSON-LD（`SoftwareApplication`）**：由 `Base.astro` 全站注入。字段：`name`、`description`=规范文案、`applicationCategory=DeveloperApplication`、`operatingSystem`、`offers`（免费）、`sameAs=[GitHub, crates.io]`。
- **`sitemap.xml`**：`@astrojs/sitemap` 自动生成。

### 5.5 部署（`.github/workflows/website.yml`）

- **PR 触发**：`npm ci && astro build`，仅校验构建，不部署。
- **push 到 `main` 且改动 `website/**`**：构建 + `actions/deploy-pages` 部署。
- 需在仓库设置中启用 Pages（Source = GitHub Actions）——在 Phase 4 dogfooding 中完成并验证。

本 PR 主体为元数据 / Markdown / Node 站点，Rust 侧的持久化测试守护**一致性与回归**。全部走 RED → GREEN → REFACTOR：

| 测试 | 断言 | 防护目标 |
|------|------|---------|
| `test_should_not_contain_template_placeholders` | 解析全部 `Cargo.toml`：无 `Your Name` / `yourdomain`；description 非空；homepage/documentation/repository 有效 | 守护已记录的 `Your Name` 占位符与 `v{{version}}` 事故类 |
| `test_should_keep_entity_consistency` | README + 官网 JSON-LD + `llms.txt` 均含**逐字**规范一句话定位 | GEO 实体一致性 |

| `test_should_have_demo_asset` | `docs/assets/demo.svg` 存在且为合法 SVG | 演示资产不缺失 |

### 6.1 质量门

## 7. 风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| GitHub Pages / Actions 部署配置在 dogfooding 前无法本地验证 | 中 | PR 工作流先保证 `astro build` 绿；部署在 Phase 4 真机启用并验证，失败不阻塞合并但阻塞 #97-B |
| `demo.svg` 生成依赖本地 asciinema/svg-term 工具链 | 中 | 提交 SVG 产物入库；脚本可复现；CI 不依赖该工具链 |
| 官网 `base=/gitflow-cli` 资源路径易错 | 中 | Astro `base`/`site` 集中配置；PR 构建校验；首页 hero 资产走相对根 |
| 元数据变更未 publish 前 crates.io 不生效，易被误解为"已完成" | 低 | 文档与 PR 描述明确：元数据随 #97-B 的 1.0.0 发布生效 |
| 实体一致性文案散落多处易漂移 | 中 | `test_should_keep_entity_consistency` 强制守护单一规范句 |
