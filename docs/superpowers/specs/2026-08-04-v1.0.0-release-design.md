# Design Spec — v1.0.0 Release

**Date:** 2026-08-04
**Issue:** #113
**Status:** Draft
**Approach:** 方案 A（分阶段渐进式）

## 概述

发布 v1.0.0：crates.io 五个 crate + Homebrew 同步上线，兼容性矩阵与支持政策随 1.0 公告公开（管理社区预期）。

## 总体架构

### 三阶段流程

```
┌─────────────────────────────────────────────────────────────┐
│ 阶段 1：前置修复                                            │
│ - 修复 #111（issue comment stale id）                      │
│ - 执行 dogfooding 验证修复                                  │
│ - Gate: #111 关闭 + dogfooding PASS                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 阶段 2：文档准备                                            │
│ - SUPPORT.md（GitHub 标准 + 支持政策 + EOL 矩阵）          │
│ - 官网支持政策页面（website/src/pages/support.astro）       │
│ - 兼容性矩阵 JSON → Markdown（v1.0.0）                     │
│ - demo.svg 重新生成                                         │
│ - GitHub 仓库描述更新                                       │
│ - Gate: 所有文档 PR 合并                                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 阶段 3：发布执行                                            │
│ - 完整 dogfooding checklist（三平台风险项）                 │
│ - make release（v0.9.0 → v1.0.0）                          │
│ - 推送到 GitHub（触发 Homebrew + crates.io）               │
│ - 验证 GitHub Pages 部署                                    │
│ - 发布公告（兼容性矩阵 + 支持政策）                         │
│ - Gate: v1.0.0 上线 + Pages 部署成功                        │
└─────────────────────────────────────────────────────────────┘
```

**关键原则：**
- 每个阶段有明确的 Gate，不跳过验证
- 文档准备充分后再发布
- 发布前必须通过完整 dogfooding

## 阶段 1：前置修复（#111）

### 问题

`gf issue comment` 返回 stale comment id（首条而非新建）

### 修复方案

- 定位 `crates/github/src/` 中 `issue comment` 命令的实现
- 修复 comment ID 获取逻辑（当前返回了旧评论而非新建评论的 ID）
- 添加测试覆盖（成功 + 失败路径）

### 验证流程

1. 修复代码 + TDD（RED → GREEN → REFACTOR）
2. `make test` 全部通过
3. Dogfooding 验证：
   - `gf issue comment <test-issue> --body "test comment"`
   - 确认返回的 ID 与新建评论一致
4. 创建 PR，合并后关闭 #111

### Gate 条件

- ✅ #111 关闭
- ✅ dogfooding 验证 PASS
- ✅ 测试覆盖新增

## 阶段 3：发布执行

### 3.1 完整 Dogfooding Checklist

**前置条件验证：**

```bash
# 1. Phase 1-3 已完成
git log --oneline | grep "chore: release"  # 确认无未发布变更

# 2. 三平台认证状态
gf auth status --platform github   # ✅ 正常
gf auth status --platform gitlab   # ✅ 正常（需先配置）
gf auth status --platform gitcode  # ✅ 正常

# 3. 工作目录干净
git status  # 无未提交变更
```

**GitHub 风险项验证：**

```bash
# 创建 release
gf release create v1.0.0-test --notes "test release"

# 验证 GitHub 网页可见
# 非交互模式验证
echo "y" | gf release create v1.0.0-test2 --notes "test"

# 清理
gf release delete v1.0.0-test --yes
gf release delete v1.0.0-test2 --yes
```

**GitLab 风险项验证（中文标签 CRUD）：⏭️ 跳过（环境不可用）**

> GitLab 测试环境不可用，中文标签 CRUD 验证跳过。GitLab 支持已在代码中实现，待环境就绪后可单独验证。

```bash
# 以下命令跳过，记录为环境约束
# gf label create "测试标签" --color "#ff0000"
# gf issue create --title "Dogfooding test" --labels "测试标签"
# gf issue view <n>
# gf issue close <n>
# gf label delete "测试标签" --yes
```

**GitCode 风险项验证（pr merge 非交互）：**

```bash
# 创建测试 PR
gf pr create --title "Dogfooding test" --body "test"

# 非交互 merge（在无 TTY 的 shell 中）
gf pr merge <n>  # 确认不提示，直接完成

# 清理：删除测试分支
```

**Bug 记录：**
- 发现 bug 时记录到 `.cache/bug-reports/pending.json`
- 任何失败项 → Release Decision: BLOCKED

**Gate 条件：**
- ✅ GitHub 风险项 PASS
- ✅ GitCode 风险项 PASS
- ⏭️ GitLab 风险项跳过（环境不可用，记录为环境约束）
- ✅ 无新增 bug
- ✅ Dogfooding Report 生成（`docs/dogfooding-report-v1.0.0.md`）

### 3.2 实际发布流程

```bash
# 1. Pre-flight 检查
make test          # 全部测试通过
make clippy        # 无警告
git status         # 工作区干净

# 2. 交互式发布
make release
```

**make release 自动执行：**
1. ✅ Pre-flight 检查（测试、clippy、工作区状态）
2. ✅ 智能版本推断（基于 conventional commits → major bump）
3. ✅ 交互式版本选择（确认 v1.0.0）
4. ✅ Changelog 预览（git cliff 生成）
5. ✅ Dry-run 确认（cargo release --dry-run）
6. ✅ 执行发布：
   - 版本号 bump（0.9.0 → 1.0.0，workspace + 各 crate）
   - 提交版本变更
   - 生成 CHANGELOG.md
   - 提交 changelog
   - 推送到 GitHub
   - 创建 tag v1.0.0
7. ✅ crates.io 发布（用户确认后）：
   - gf-core → gf-github → gf-gitlab → gf-gitcode → gf（依赖顺序）

**GitHub Actions 自动触发：**
- ✅ Build 6 个平台二进制（macOS arm64/x86_64, Linux arm64/x86_64, Windows）
- ✅ 创建 GitHub Release（附带二进制 + checksums）
- ✅ 更新 Homebrew formula（`HomebrewFormula/gf.rb` → v1.0.0 + SHA256）
- ✅ 发布到 crates.io（5 个 crate）

**Gate 条件：**
- ✅ Tag v1.0.0 已推送
- ✅ GitHub Release 已创建
- ✅ crates.io 5 个 crate 发布成功
- ✅ Homebrew formula 已更新

## 错误处理与回退策略

| 失败场景 | 回退策略 |
|---------|---------|
| 阶段 1 dogfooding 失败 | 修复 bug，重新验证，不进入阶段 2 |
| 阶段 2 文档 review 不通过 | 修改文档，重新 review，不进入阶段 3 |
| 阶段 3 dogfooding 失败 | 修复 bug，重新验证，不发布 |
| `make release` 失败 | 检查错误，修复后重试；如有 tag 已推送，手动删除 tag 和 commit |
| crates.io 发布失败 | 手动重试 `cargo publish`；版本不可撤销，只能 yank |
| Homebrew 更新失败 | 手动更新 `HomebrewFormula/gf.rb` 并提交 |
| GitHub Pages 部署失败 | 检查 workflow 日志，修复后重新触发 |
